## 什么是递归

**递归** = 函数在执行过程中**调用自己**，把大问题拆成更小的同类型问题。

> 就像俄罗斯套娃：打开一个，里面还有一个更小的；最小的那个（基准）不再打开。

---

## 递归的两个要素

```python
def factorial(n):
    if n <= 1:        # ① 基准条件：问题小到可以直接回答
        return 1
    return n * factorial(n - 1)   # ② 递归步骤：缩小问题规模
```

`factorial(5)` 的执行过程：

```
factorial(5)
= 5 * factorial(4)
= 5 * 4 * factorial(3)
= 5 * 4 * 3 * factorial(2)
= 5 * 4 * 3 * 2 * factorial(1)
= 5 * 4 * 3 * 2 * 1      ← 触底（基准），开始逐层返回
= 120
```

## 例：斐波那契数列

`1, 1, 2, 3, 5, 8, 13...`：每一项 = 前两项之和。

```python
def fib(n):
    if n <= 2:          # 基准：前两项都是 1
        return 1
    return fib(n - 1) + fib(n - 2)   # 递归

print(fib(1))   # 1
print(fib(7))   # 13
```

⚠️ **注意**：这个版本重复计算很多（fib(3) 会被算好几次），n=40 时就非常慢。下一课学了"记忆化"或改用循环可以解决。

## 递归 vs 循环

| 对比 | 递归 | 循环 |
|---|---|---|
| 代码可读性 | 符合数学定义，简洁 | 有时更直白 |
| 性能 | 有函数调用开销 | 通常更快 |
| 适用场景 | 树、分治、回溯 | 简单重复 |

很多递归能改成循环，反过来循环也能改递归。先会写，再考虑性能。

## 关键要点

- 递归要素：**基准条件**（停止）+ **递归步骤**（缩小）
- 写递归先想"最小情况怎么答"，再想"如何变小"
- 小心重复计算和过深递归（Python 默认递归深度约 1000）
